# GDS3710 Provisioning Generator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Grandstream GDS3710 door-panel support to voip-provisioner, so the panel can autoprovision its SIP account (domain, server, account, secret) via the existing HTTP config-fetch mechanism already used by desk phones.

**Architecture:** New `GDSGenerator` (own P-value namespace, verified against the official Grandstream/BroadSoft GDS37xx reference config — do not confuse with `GrandstreamGenerator`'s GXP P-values), new `templates/grandstream_gds/cfg.xml.j2`, registered as vendor key `"grandstream_gds"` in `server.py`, with model-string routing (`"gds"` in model → this vendor) checked before the generic Grandstream (GXP/GRP) check.

**Tech Stack:** Python 3.12, FastAPI, Jinja2, pytest.

## Global Constraints

- P-values are exactly as verified in the design spec (`/home/administrator/annuntia/docs/superpowers/specs/2026-09-04-gds3710-autoprovisioning-design.md`), sourced from the official BroadSoft Partner Configuration Guide for the Grandstream GDS37xx Door System, Appendix A reference config — do not substitute GXP P-values (P47/P36/P34/P52/P2/P3/P4/P142) for these, they are a different namespace on this device family.
- No door-relay, camera, or RTSP configuration in this template — out of scope, handled separately by `backend/routers/door.py` in the Annuntia repo via its own HTTP challenge/response API, unrelated to SIP provisioning.
- No phonebook support for this device (`PHONEBOOK_TEMPLATE = None`, no `/grandstream_gds/phonebook.xml` route) — GDS37xx door panels don't have a phonebook feature in this integration.
- Model string convention already used by the ProvisioningView frontend for every other vendor: `<vendor>_<model>` lowercase, e.g. `grandstream_gxp1610`. The GDS3710's model string is `grandstream_gds3710`.

- [ ] **Step 2: Write the generator**

Create `src/provisioner/generators/gds.py`:

```python
"""Grandstream GDS37xx door system configuration generator.

Distinct P-value namespace from GXP-series phones (generators/grandstream.py) —
verified against the official BroadSoft/Grandstream GDS37xx reference
configuration. Do not merge with GrandstreamGenerator or reuse its P-values.
"""

from typing import Any

from .base import BaseGenerator


class GDSGenerator(BaseGenerator):
    """Generator for Grandstream GDS37xx door systems (GDS3705/GDS3710)."""

    VENDOR = "grandstream_gds"
    TEMPLATE_DIR = "grandstream_gds"
    CONFIG_TEMPLATE = "cfg.xml.j2"
    PHONEBOOK_TEMPLATE = None  # door panels don't have a phonebook in this integration

    @property
    def config_content_type(self) -> str:
        return "application/xml; charset=utf-8"

    def generate_config(self, settings: dict[str, Any]) -> str:
        return self.render_template(self.CONFIG_TEMPLATE, **settings)
```

```python
def _detect(mac: str, model: str, config) -> str | None:
    vendor = detect_vendor(mac, _build_oui_map(config))
    if not vendor:
        m = model.lower()
        if "yealink" in m:
            vendor = "yealink"
        elif "fanvil" in m:
            vendor = "fanvil"
        elif "gds" in m:
            vendor = "grandstream_gds"
        elif "grandstream" in m or "gxp" in m or "grp" in m or "ht" in m:
            vendor = "grandstream"
    return vendor
```
